## 1. 为什么有这个模块

TODO 是平台第一个业务模块,目的是**打样**:验证底座、确立后续领域模块(catalog、order 等)照抄的约定。

它要验证的不是模块生命周期——那已经被 11 个 `internal/infra/*` 模块跑通了。它要验证的是此前从未触及的部分:**带业务语义的写入、并发控制、动态查询、批量导入导出**。改造前全仓 23 个已注册 HTTP 操作全部是 GET,零写入端点。

## 3. 查询语法:为什么算子必须写

这是本模块**唯一跨模块的强约定**,后续所有列表接口都会照抄,所以理由必须留档。

三个属性只能取其二:

| 形态 | 参数数量 | 歧义 | 冗长 |
|---|---|---|---|
| 算子在参数名 `title_like=x` | ❌ 字段×算子 | ✅ | ✅ |
| 算子在值,**强制** `title=like:x` | ✅ | ✅ | ⚠️ |
| 算子在值,可省略 `title=x` | ✅ | ❌ | ✅ |

**最初实现的是第一种**,TODO 只有 6 个可过滤字段就产生了 20 个参数——预言中的"宽表参数爆炸"在最窄的表上就发生了。

**可省略被否决,因为它静默出错**:用户在搜索框输入 `eq:123`,`title=eq:123` 会被解析成"等于 123",不报错、直接返回错误结果。前端要自保就得知道每个字段的算子集合并预先转义——把复杂度推给每一个调用方。

**括号语法 `filter[k]=v` 被否决**:Go 的 `net/url` 不特殊处理括号,huma 按字段名绑定,`filter[priority]` 落不到结构体上,只能自己读原始 query,等于绕开整个框架层。

所以接受冗长。而这个冗长**主要落在手写 URL 上**——前端构建筛选 UI 时本来就知道算子(下拉框选的或代码写死的),拼上去零成本。

**只切第一个冒号**:`due_at=gte:2026-09-01T00:00:00Z` 的值自带冒号。要搜字面量 `eq:123` 就写 `title=eq:eq:123`。

## 4. 安全约束

调用方**无法影响 SQL 结构**:列来自生成的类型化字段,算子来自该字段的白名单,只有值是调用方给的且始终作为参数绑定。以下是结构之外的约束,每条都有对应测试:

| 约束 | 防什么 |
|---|---|
| 未声明的参数 → 400 | 忽略未知参数,会让拼错的字段名静默返回全量数据,也让注入的参数无声通过 |
| 同字段同算子重复 → 400 | "取最后一个"正是注入覆盖能得逞的原因 |
| 错误信息**不回显调用方原值** | 过滤错误正是前端会直接塞进 DOM 的那类消息 |
| LIKE 值剥离 `%` `_` | 通配符会把查询放大成全表扫描。**剥离而非转义**:MySQL/PostgreSQL 默认反斜杠转义,SQLite 没有默认转义符、必须显式 `ESCAPE`,而查询构建器不生成该子句——跨方言无法统一 |
| 值长度封顶 256 | 超长值会进 LIKE 模式并污染日志 |

**前端必须做 URL 编码**。未编码时用户输入里的 `&` 能真的分割出新参数(`foo&status=eq:done`)——这是任何查询参数都有的问题,不是本语法特有。标准 HTTP 客户端自动处理。

## 5. 三条正确性保证

**排序必须全序。** SQL 中"未指定排序"不是任意顺序而是**未定义顺序**;配合 offset 分页会导致行重复或被跳过,且无任何报错——这是数据错误,不是显示问题。因此:标识符无条件追加为末位排序键,且代码中不存在"不排序"的路径。

**可空列排序需前置 NULL 键。** 三方言默认行为互不相同:

| | ASC | DESC |
|---|---|---|
| PostgreSQL | NULLs LAST | NULLs FIRST |
| MySQL / SQLite | NULLs FIRST | NULLs LAST |

不显式指定,同一请求在不同数据库上返回不同顺序。做法是加前导键 `(col IS NULL)`(false 排在 true 前,三方言一致)。gen 只提供 `Asc()`/`Desc()`,MySQL 又不支持 `NULLS LAST` 语法,所以只能这样。

**时间范围必须能写成半开区间。** 一个自然月是 `[9-01, 10-01)`。只有 `gte`/`lte` 时,上界得写成"最后一个可表示的瞬间",而那个字面量和真实边界之间的任务会被静默漏掉——漏多少取决于列的精度,换个方言就变。因此时间字段同时暴露 `gt`/`lt`。

整数字段不需要:`lte:5` 和 `lt:6` 在离散域上是同一个查询,多给一个算子只是多一种写法。**闭区间对离散量无害,对连续量有害。**

## 6. 实现中撞到的框架约束

**留档的价值最高的一节**——每条都花了实际调试时间,下一个模块会原样撞上。代码里都有对应注释。

| 约束 | 表现 |
|---|---|
| `guid.ID` 不能做路径/查询参数 | huma 按 Go kind 解析(int64→数字),再按 schema 校验(string),**任何值都 422**。参数声明为 `string` 后自行 `Parse` |
| 参数不能用指针 | huma 直接 panic(其源码 TODO 注明是待实现项)。"指针区分未提供与零值"只在 body 里成立 |
| 输入结构体的嵌入类型**必须导出** | 未导出时 huma 够不到字段且**不报错**,参数与 header 静默为空。与嵌套层数无关 |
| 省略 `contentType` tag 不走默认值 | `strings.Split("", ",")` 返回 `[""]`,accept 列表匹配不上任何东西 → 拒绝一切上传。用 `application/octet-stream`(huma 的通配约定) |
| `humatest` 的 `[]byte` 参数 | 被当作待 JSON 序列化的值,不是原始 body。multipart 必须传 `io.Reader` |
| 参数 tag 是**字面名**,不是 sentinel | `query:"-"` 不表示"跳过",它声明了一个名叫 `-` 的参数——出现在 Swagger 里,一旦发送就 422。**不打 tag** 才是退出方式 |
| 静态路由需先于参数路由注册 | 否则 `/todos/import-template` 被 `/todos/{id}` 捕获 |
| i18n 本地键不能含点 | 只允许 `[a-z]` 起头 + `[a-z0-9_]`,命名空间由 `RegisterFS` 添加 |

## 7. 平台修复

**`guid.ID` 零值 JSON 不可往返**:`MarshalJSON` 输出 `"0"`,而 `Parse` 拒绝非正数——该类型会产出自己读不回来的 JSON。任何可空引用列(`parent_id`、`assignee_id`)都会踩。

修法:零值序列化为 `null`(`Parse` 早已接受 `null` → 0,不一致的是 `MarshalJSON`)。响应中一个未知的 actor 因此是 `"created_by": null` 而非字段消失,客户端能区分"未知"与"未请求该字段"。
