# 高危失效模式

按**失效机理**组织,与业务领域无关。任何系统只要具备对应的技术特征,这条模式就适用。

`deep-review`、`deep-audit` 和 `deep-test` 共用这一份。

> **这是线索来源,不是必报清单。** 用它想到"这条路径可能整体失效",然后**照常去证伪**;
> 报告里只收拿得到证据的那些。逐条抄进报告等于制造噪音,那正是反 checklist 约束要防的东西。

## 它补的是什么

等价类、边界值、判定表覆盖的是**单个输入或单个判断**。真实的高危缺陷常常发生在这些方法覆盖不到的地方 ——
不是某个字段填错了会怎样,而是**一整条路径在特定条件下整体失效**。
把某个字段的边界和注入都验穿了,也发现不了"暂存的数据提交后附件丢了"。

| 关注点 | 看哪份 |
|:---|:---|
| 单字段取什么值、恶意输入用什么 payload | `boundaries.md` |
| 怎么设计验证(等价类、判定表、状态转换、场景法) | `test-design.md` |
| **整条路径在什么条件下整体失效** | 本文件 |

---

## 分配精力的原则:按不可逆性,不按频次

**判据是「失效后能不能补救」,不是「这类缺陷出现得多不多」。**

| 后果 | 例子 | 能否事后补救 |
|:---|:---|:---|
| **不可逆** | 数据丢了、越权方已经看到了、钱算错并已入账、重复扣款、审计链断了 | **不能**。修好代码消除不了已发生的损失 |
| 可逆 | 文案没翻译、按钮被遮挡、排序不对、提示不友好 | 能。下个版本修掉,期间忍一忍 |

**为什么不能用缺陷统计定优先级** —— 统计有双向偏差,两个方向都会误导:

- 某类缺陷**数量少**,可能是它不容易出错,也可能是**根本没验过** —— 没被发现的不会进缺陷库
- 而在验得少的领域,**唯一能被发现的是严重到瞒不住的那些**(数据丢了有人喊,同场景下的文案错位永远没人报),
  于是该领域的"致命率"看起来虚高

"某类缺陷致命率 86%"这种数字既可能低估也可能高估。**不可逆性这个判据不依赖任何统计,也不会被样本偏差污染。**

因此分两级:**A 类失效不可逆,触及即须逐条单独验证,不接受抽样;B 类失效可逆,清单式覆盖即可。**

---

## A 类:失效不可逆(触及即必验)

### A1 · 先本地暂存,再批量提交

**技术特征**:数据先落在一侧(客户端缓存、草稿、待同步队列、内存缓冲),之后再批量提交到另一侧。

**失效机理**:两侧之间有一个**没有事务保护的窗口**。窗口内任何环节失败 —— 提交失败、部分成功、
提交成功但未落盘、缓存清理时机错误 —— 都会让已完成的工作永久消失,且往往无法重做(现场条件已不存在)。

**为什么容易漏**:开发与测试环境网络稳定,这条路径几乎不触发。而它一旦失效就是数据丢失。

**必验**:全程离线完成一次完整流程再提交,**逐字段核对两侧一致**(不是只看"提示成功");
提交中断(断网/杀进程/切后台)是否产生半成品、能否续传、重试会不会重复提交;
暂存期间同一条数据在另一侧被改动 → 冲突处理;**提交成功后缓存的清理时机 —— 清早了丢数据,清晚了重复提交**。

### A2 · 大体积 / 大批量提交

**技术特征**:任何允许提交不定大小内容的入口 —— 文件上传、批量导入、富文本、批量操作。

**失效机理**:请求体超过链路上某一环的限制(网关 body 上限、超时、内存、字段长度),
且失败常发生在**中间层**,错误无法被上层正确解释,表现为白屏、静默失败或误导性提示。

**为什么容易漏**:**样本大小不真实** —— 验证时用几十 KB 的文件,真实提交的是数 MB 原图或上万行表格。

**必验**:用**真实体量**样本;单次数量上限与总体积上限,以及上限 +1;超限时有明确的、面向用户的提示;
弱网下的超时与重试;**核对是否真的完整接收(查落库内容,而非只看响应码)**。

### A3 · 状态机的中断路径

**技术特征**:任何有明确状态流转的对象 —— 审批、订单、任务、多步骤流程。

**失效机理**:正向路径通常被充分验证,但状态往往在"进入下一步"时就被提前写入。
中途退出(返回、切后台、超时)后,对象停在一个**没有恢复入口的中间态**,当事人被永久卡住,只能改数据解开。

**为什么容易漏**:执行时习惯一路走到底,很少在中间步骤退出再进入。

**必验**:**每一个**节点中途退出再进入,核对状态值与界面(按钮文案、可点性)是否自洽;
每条合法流转执行两遍,验证幂等或正确拒绝;非法跳转被拦截;
回退路径(撤回、驳回、取消)之后能否重新走完;两个操作者并发推进同一对象。

### A4 · 数据隔离边界

**技术特征**:多租户、多组织、多项目,或任何"只应看到自己那部分数据"的场景。

**失效机理**:隔离条件写在**查询的某一层**而非全部层。列表过滤了详情没过滤,页面过滤了导出没过滤,
主流程过滤了通知没过滤。表面功能完全正常,越权路径静默存在。

**为什么必须单独验**:不可逆 —— 数据被看到就收不回来。而且这类缺陷在正常使用中永远不会自己暴露。

**必验**:四类越权与逐接口核对见 `perspectives.md` 安全视角;
本条重点是**旁路**(导出、打印、分享链接、通知、报表、下拉数据源、附件直链)与**退出/切换后的残留**。

### A5 · 数值计算与对账

**技术特征**:金额、计费、分摊、税费、折扣、退款、汇率、单位换算。

**失效机理**:偏差以**极小的量**持续产生(浮点误差、舍入方向、分摊余数的归属),
单笔看不出来,累积到对账才暴露 —— 而此时数值已经被使用过很多次。

**必验**:**存储是定点还是二进制浮点 —— 用浮点存金额直接判不合格,不必再往下验**;
舍入方向(`2.5` / `-2.5` / `0.005`,银行家舍入与常规舍入结果不同);
分摊余数归属(100 分给 3 个,多出的最小单位归谁)与反向汇总能否还原;
计算顺序(先折后税 vs 先税后折);退款、部分退款、退款后再退款的累计不超过原额;多币种的汇率取值时点与精度。

### A6 · 幂等与重复副作用

**技术特征**:任何写操作可能被重复触发的路径 —— 重复点击、网络重试、消息重复投递、回调重放、调度重跑。

**失效机理**:业务副作用执行了两次。

**必验**:同一请求连发两次,核对副作用**只发生一次**;
**幂等冲突要返回与首次一致的结果,而不是报错** —— 报错会让调用方以为失败而再试;
回调重放;消息重复消费;超时后客户端重试但服务端其实已成功;幂等键的作用域与有效期。

### A7 · 存量数据与版本兼容

**技术特征**:任何已经运行过一段时间的系统。规则改了、字段加了、枚举扩了、schema 迁移了。

**失效机理**:新代码遇到按旧规则创建的数据 —— 旧记录缺字段、旧枚举值不在新取值集合里、旧格式解析失败。

**为什么系统性漏掉**:**验证用的数据都是新造的** —— 按当前代码、当前规则创建。
所以这条路径在测试环境里天然不存在,直到线上遇到真实老数据。这不是"想到了没验",是它在那儿根本不会出现。

**必验**:用**变更前的格式**造一批记录,再用新代码读、改、删、导出;
新增必填字段后旧记录为空时的各条路径;枚举扩容后旧客户端/旧缓存拿到没见过的值;
规则放宽或收紧后越界的历史数据能否展示与修改;灰度期间新旧版本先后写同一条数据。

### A8 · 定时任务与异步作业

**技术特征**:定时任务、延迟队列、异步作业、批处理。

**失效机理**:漏跑、重跑、跑两次、执行到一半失败、重试风暴、执行顺序与预期不同。
而这些**没有人在场**,失败时没人看见,数据静默损坏。

**为什么容易漏**:手工验证是同步的 —— 触发一下看结果。异步作业既没有"触发一下"这个动作,也没有立即可见的结果。

**必验**:执行到一半失败(已处理部分是否回滚,重跑会不会重复处理);
同一任务被触发两次(调度器重启、多实例部署);超时后仍在执行而调度器已判失败并重新调度;
上游数据未就绪时被触发;跨天/跨月边界(统计口径、时区);积压后的批量处理与限流;
**失败后的告警是否真的发得出来 —— 这条最容易被忽略,因为它只在别的东西坏掉时才起作用**。

## B 类:失效可逆(清单式覆盖)

- **多步骤流程的中断保护** —— 每一步中断后重进,已填数据是否保留;跳子页再返回主流程数据是否还在;
  提交失败后是否清空让人重填。**凡涉及已投入较多录入成本的流程,按 A 类对待。**
- **界面适配与遮挡** —— 固定元素在各种屏幕形态下的可见性、内容超出一屏能否滚到底、长文案换行截断、字体放大、深色模式。
- **国际化** —— 硬编码文案残留;**文案长度变化导致的溢出**(不同语言长度差异可达两倍);
  日期/数字/货币格式是否随语言本地化(最易漏,且严重度高于文案问题);术语是否统一。
- **身份与凭证链路** —— 注册/登录/改密/找回/验证码。重点:**操作提示与实际结果必须一致**
  (提示"发送成功"但实际没发出,高频且高危);改密后新凭证可用**且**旧凭证被拒,两条都要验;
  重复注册已存在的标识必须被唯一性拦截;会话过期、多端登录、被踢下线后的表现。
- **列表** —— 搜索命中/不命中/特殊字符、单与多条件过滤、排序、分页边界、空态、重复渲染、字段取值。
- **表单与弹窗** —— 校验定位到具体字段、长度上限按定义值取边界、**默认值正确性**(易被当作不用验,实际是高频缺陷)、
  取消与关闭的行为差异、重复提交防护。
- **导入导出** —— 模板可下载、错误行**定位到第几行第几列**、部分成功的处理、导出字段与列表一致、脱敏规则、大数据量(与 A2 叠加)。

## 判定与留痕

对 A 类八条逐条判定是否触及,**判定为不触及也要写明理由**。
否则读者无法区分"评估过认为无关"与"根本没想到" —— 这两者的风险完全不同。

| 出现这些特征 | 触及 |
|:---|:---|
| 本地存储 / 草稿 / 离线可用 / 待同步 / 写缓冲 | A1 |
| 文件上传 / 批量导入 / 富文本 / 批量操作 | A2 |
| 状态字段 / 审批 / 多步骤 / 工作流 | A3 |
| 多租户 / 多组织 / 数据权限 | A4 |
| 金额 / 计费 / 分摊 / 税费 / 退款 / 汇率 | A5 |
| 回调 / 消息消费 / 可重试的写操作 | A6 |
| **任何已上线过一段时间的系统**(规则变过、字段加过、枚举扩过) | A7 |
| 定时任务 / 延迟队列 / 异步作业 / 批处理 | A8 |
