# 试点评估计划（规划，不代表试点已运行）

> 2026-10-12；依据已接受需求审计 B3 / B4、D126 / D128。[PRD](PRD.md) §15 / §17，[共享契约](specs/00-conventions.md) §16 为产品口径。

## 1. 目标与样本

验证跨 runtime 的需求签认 → 软件执行 → 内部质量门 → 团队接受 → 客户验收闭环是否降低监督负担和交付成本。招募 2–3 个符合 ICP 的 AI 软件工作室 / 外包团队，每团队一个真实但可控的项目，客户同意使用外部成员视图；不以内部演示账号替代真实甲方回执。目标是至少 2 个团队持续使用，而不是旧「1/3 转付费」与持续使用混为一个门槛。

MVP 开发 W8 只启动试点、输出首版报告；持续观察另需 4 周。每团队基线取此前 2–4 周相近项目的至少 20 个有明确验收标准的工作项；产品观察至少 20 个首次进入内部 QA 的工作项、其中至少 10 个有 L3 结果，覆盖 2 次真实甲方交付回执。达不到样本时延长观察或报「样本不足」，不得把观察阈值当统计显著性；样本数不是产品已达到事实。

负责人角色：产品负责人负责样本选择与结论，团队交付负责人记录工时 / 基线 / 范围变化，工程负责人确认版本 / 审计 / 数据质量，甲方仅确认自己真实签认与回执。实际人选在招募启动前填入版本报告，不虚构姓名或完成时间。

## 2. 基线与对照方法

记录现行工具（终端 / 聊天 / 工单）及人机配置、工作项类型 / 风险 / 大小、客户等待、模型 / runtime / verifier 版本、人工单价和 AI / 算力账单。用同团队、相近风险与规模的历史项目作匹配对照，可能时交错同类任务的旧工具与产品流程；不能把不同团队、不同比例的复杂工作简单平均当产品效果。

冻结指标版本、观察窗口、cohort 纳入规则和排除项后才观察。cohort 包括首次进入内部 QA 的全部工作项及其失败 / 返工 / 未接受成本；范围变更、取消、跳过、缺工时与甲方等待分别报告，不为了提高通过率事后剔除失败项。不采集客户代码 / 消息正文，取对象 ID、版本、耗时、成本、结果与审计关联。

## 3. 指标与数据质量

| 指标 | 报告口径 | 检查 |
|---|---|---|
| L2 首轮内部通过率 | 首个分支首轮 QA 全通过 / 首次进入内部 QA 工作项 | 内部失败再通过不是首次；人工覆盖不计自动通过 |
| L3 首次接受率 | 第一次团队裁决即接受 / 有第一次团队裁决工作项 | 单独展示人工覆盖数量与率 |
| L4 首次甲方验收率 | 首次交付回执接受 / 有首次回执的包，条目率另表 | 包与条目不混分母，部分接受不等于全部接受 |
| 每个 L3 已接受成本 | cohort 全 AI + 机器 + 平台分摊 + 人工折算 / L3 工作项数 | 含失败 / 未接受 / 内部轮次；缺人工报下界及缺失率 |
| 监督分钟与周期 | 人审 / 授权 / 澄清总分钟；需求签认至 L3 / L4 | 后台打开时长不能冒充实际关注时间；甲方等待单列 |
| 内部轮次 / 穿透 | 轮次总、中位、P95；QA 后质量拒绝按 L3 / L4 分开 | 范围变更不计质量穿透，根因复核后归类 |
| 证据与审计 | 提交标准证据映射覆盖；关键终态审计完整性 | 目标覆盖 ≥90%、关键终态完整 100%；不是已验证结果 |
| 持续使用 | 连续 4 周每周处理至少 5 个真实工作项且产生真实裁决 | 至少 2 团队，无人员代操作伪装自然使用 |

对照每项报告分母、缺失率、模型 / 模板 / verifier / 指标版本、区间与中位数，团队分别出表。样本小时只报告描述性差异与案例，不宣称因果 / 显著性。审计缺失、工时缺失 >10% 或模型 / schema 中途变化，标注不可直接比较并单独分段。

## 4. 继续 / 调整 / 停止判据

以下是预注册的**待验证门槛**；若 W1 / 招募中发现样本不可行，须由产品负责人在观察前发布新版本及理由，不追溯改结果。

| 决策 | 判据 | 下一动作 |
|---|---|---|
| 继续 v1.1 | 至少 2 团队达持续使用；至少 2 团队成本或监督分钟较匹配基线下降 ≥20%；L4 / 穿透不劣化；工程证据与审计目标满足；无严重隔离 / 授权缺陷 | 产品负责人签认下一阶段范围，不把所有 v1.1 同时启动 |
| 调整 / 延长 | 样本不足、数据缺失、只有 1 团队持续用，或成本改善不足 / 操作复杂导致监督增加，但无严重安全问题 | 明确根因与最多 2 项改动、再观察 2–4 周，不换分母美化结果 |
| 停止扩张 | 严重越权 / 泄露、不可追溯正式交付、裁决审计断链；或连续两次调整后仍无 2 团队持续使用且无成本 / 监督改善 | 先止损修复 / 回退试点，再由负责人决定重新试验或停止商业扩张 |

安全缺陷立即停止受影响路径而非等版本报告；甲方拒收本身不是平台失败，须区分质量、范围与外部原因。任何人工覆盖不能免除工程安全门禁。

## 5. 版本报告与访谈

每周发布 `Pilot Report <version>`，包含产品 / schema / WorkflowDef / runtime / model / verifier 版本、窗口、团队样本、分母 / 排除 / 缺失、基线表、指标差异、返工及覆盖案例、甲方反馈、操作负担、风险、决定与责任人。关键失败附脱敏对象 / 审计证据，不附客户正文。版本报告保存实际产物后才能声称试点完成，本文只规定模板。

招募前访谈、第一真实回执后访谈与第 4 周访谈分别验证：现有交付痛点、减少 / 增加的操作、实际付费意愿和替代工具。将竞品优势当假设，主动记录反例和不用产品的理由。付费报价与商业阶段闸门使用[商业验证计划](commercial-validation-plan.md)，持续使用不能被转付费率替代。
