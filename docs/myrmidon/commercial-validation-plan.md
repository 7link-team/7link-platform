# 商业验证计划（假设与实验，不是收入预测）

> 2026-10-12；依据已接受需求审计 B6 / B8、D128。产品范围见 [PRD](PRD.md)，真实价值证据见 [试点评估计划](pilot-evaluation-plan.md)。商业实验与定价不写入产品执行规则。

## 1. 待验证假设

| 假设 | 验证证据 | 可推翻的结果 |
|---|---|---|
| ICP 愿为跨 runtime 的客户交付治理付费 | 真实团队现有监督 / 返工成本、独立购买人预算、带条件试点承诺 | 需求只在单人终端或已有工具已足够解决 |
| 签认、权限裁决、证据与客户验收形成差异化 | 对照现有工单 + Agent 工具完成同一交付的时间 / 成本 / 客户反馈 | 新增操作大于节省监督，无需客户回执 |
| 软件工作室是首发可服务市场 | 2–3 团队试点及至少 2 团队持续使用 | 只有演示兴趣或需要大量定制 / 非软件功能才会用 |
| 开源控制面 + 付费托管 / 运维服务可行 | 自托管与托管偏好、运维成本、采购 / 安全要求 | 只接受免费自托管或成本超过可实现价格 |

竞品「不会做」不是事实。访谈直接比较终端 Agent、项目管理、Agent 编排和自建脚本；记录选择它们的理由、转换成本与数据迁移需求。

## 2. 客户访谈与试点漏斗（第 1–2 月）

目标完成 12–15 次 ICP 访谈，其中至少 5 位交付负责人、5 位预算 / 采购负责人，可为同团队不同角色；再招募 2–3 个可做真实项目和甲方回执的团队。问题围绕上一真实项目：如何签需求、谁接受结果、实际监督时间、返工成本、现有预算与采购约束，不用「你会喜欢吗」代替证据。

记录访谈日期 / 角色 / 当前工具 / 可量化痛点 / 现有支出 / 对外验收要求 / 拒绝理由 / 可试点项目。以匿名汇总作报告，引用案例需客户允许。实质线索是提供真实项目、参加基线采集或接受书面试点条件，不是点赞 / 邮箱数。本文未授权自动联系客户、发送报价或收款；执行这些动作由实际商业负责人在开展实验时负责。

## 3. 定价实验（第 2–3 月）

先解释平台费用与客户自付模型 / 算力费用的边界，再用标准软件闭环演示。分别测试按团队订阅、自托管支持套餐、托管服务套餐三种价值主张，固定同一可交付范围、记录价格区间与拒绝理由；不同时改价格和能力而无法解释结果。

由商业负责人在实验前基于实际成本发布 2–3 个价格档和区间，随机或顺序平衡访谈样本，记录实际选择、书面试点 / 采购意向、是否愿付小额可退订金。价格数值与退款条款是商业决策，本文不凭空定价或授权收款。试点转付费分母是完成试点且被正式报价的团队，未报价 / 样本不足单列；至少一项真实付费或有采购期限的书面承诺才能称价格验证，不拿持续使用替代支付证据。

## 4. 开源边界与 GTM 实验

开源候选边界为通用控制面、基础 runtime 适配、WorkflowDef schema 与审计 / 证据协议；付费候选为托管、运维支持与经验证的团队需求。现有第三方许可证、凭据、安全隔离与客户数据不因商业实验放松。最终许可证 / 开源范围在公开发布前用 ADR 和许可证审查确认；当前不宣称已开放源码或已有商业授权方案。

GTM 首试目标为熟悉跨 runtime 的 AI 软件工作室：可复现的软件交付案例、试点伙伴推荐、技术社区内容、直接访谈。每个渠道记录接触数 → 合格访谈 → 真实项目试点 → 持续使用 → 付费，附人力耗时与获客成本；对外发布或消息发送必须实际授权，不自动批量触达。每两周只比较可控的一项渠道 / 价值主张变化。

## 5. 3–6 月商业闸门

以下是**待验证门槛**，不是已实现承诺，也不替代产品安全与技术验收。

| 时点 | 继续证据 | 调整 / 停止扩张 |
|---|---|---|
| 第 1 月 | 访谈完成、明确购买人 / 可量化痛点，2–3 真实试点候选 | 无真实项目或预算主人则调整 ICP，不增加产品广度 |
| 第 3 月 | 试点至少 2 团队持续使用、成本 / 监督改善有基线证据，至少 1 个真实付费或有期限采购承诺 | 样本不足延长；只有兴趣无付费证据则修正价格 / 范围，再试一个周期 |
| 第 6 月 | 至少 3 个付费团队，其中至少 2 个连续两个月续用；可实现正贡献毛利且支持工时可控 | 无续用或收入不能覆盖直接成本，停止扩大获客 / 开发并做一次明确取舍 |

每个闸门报告样本数、报价覆盖、未完成采购、退款、流失与不使用原因，避免以试用账号增长替代真实价值。实际负责人签认继续 / 调整 / 停止，商业验证失败不自动废弃已有用户的数据与服务承诺。

## 6. 财务三情景（按月更新，不虚构收入）

| 情景 | 输入假设 | 必看结果与决策 |
|---|---|---|
| 保守 | 1 付费团队、低价档、较高支持工时、模型 / 基础设施上涨 30% | 现金消耗、最长可试验月数，若贡献毛利为负先收窄服务 |
| 基准 | 3 付费团队、中价档、支持工时基于试点中位数 | 每团队贡献毛利、回本月数、续用后是否支撑下一阶段 |
| 乐观 | 8 付费团队、高价值套餐、支持工时改善但保留容量上限 | 运维 / 支持容量、增加人员后毛利，不假设边际成本为零 |

输入实际报价、客户自付 / 平台转售的模型费、基础设施账单、支持工时单价、研发固定成本、退款与税费；无数据填「未知」。月收入 = 付费团队数 × 实际月单价；贡献毛利 = 收入 − 模型转售成本 − 基础设施 − 直接支持 / 支付成本；现金消耗另加研发与其他固定成本。三情景都报假设来源与区间，不能把乐观收入当融资 / 招聘依据。

## 7. 下一次可执行评估

原型与 W1 技术评审之后，由产品 / 商业负责人确定访谈对象及实际联络授权，开始访谈并冻结试点基线；每两周生成带版本的实验报告。当前文档阶段不新增产品后端、不发布、不发送客户消息、不报价或收费。
