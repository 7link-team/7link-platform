# Prototype workflow editor

Local, isolated React Flow (@xyflow/react) runtime. The vanilla site loads only `pages-workflow.js`; React and React Flow live inside the editor iframe. No runtime CDN is needed for this feature.

From this folder: `npm ci` then `npm run build`. Commit the source, lockfile, generated bundles and third-party notices together. Serve `docs/myrmidon` over HTTP: `python -m http.server 8765 --directory docs/myrmidon`. Open `http://127.0.0.1:8765/prototype.html#/template/SOFTWARE`, then **编辑流程**. Project read-only instances are under `#/pipelines/p1`.

WorkflowDef JSON is the sole definition; canvas changes become structured patches. Published version snapshots are retained separately from the current draft in browser localStorage. Agent drafting, review and publishing are explicitly simulated, with no backend or real model invocation. Trigger nodes remain v2. Subflows retain independent version references and expose details on demand; the prototype does not load a real workflow registry.

`workflow-definition.js` supplies the shared seed and validator to both template projections and the isolated editor bundle. Template stages, versions and history project published snapshots; draft saves never advance them. JSON export downloads the complete definition; JSON file import (2 MiB maximum) validates the schema and current workflow identity and creates a draft without replacing published history. Undo/redo use up to 100 in-memory snapshots and emit complete inverse/reapply operations; new edits clear redo and require fresh human review. WorkflowPatch includes operations, author and reason. The base hash and actor are explicitly simulated; this is not a production patch engine or authorization system.

The editor limits one graph to 200 nodes. React Flow renders visible elements only. Dragging changes the in-memory canvas, records a patch on drag end, and never writes storage per frame. Instance projection uses the project's locked published WorkflowDef and displays one selected work item at a time (up to 40 choices), never 40 duplicated graphs. Node runs are separate from the immutable definition; only matching node IDs and expected kinds receive existing prototype execution/quality/gate facts. Other nodes show NOT_RUN. Missing locked versions display an explicit unavailable state. Statuses synchronize every two seconds. These constraints are not a performance benchmark. Nodes have a keyboard-operable selector, movement buttons and connection target selector in addition to pointer dragging.

Browser review checklist: node creation/selection/property changes; pointer drag and connection; cycle rejection; bounded loop validation; mandatory human gate protection; save/reload; Agent proposal rejection/acceptance; human review required before publish; immutable historical snapshots; project-only publish; project switching and instance links; empty projects and JSON errors.
