> 适用对象:PRD / 原型图 / UI 设计稿。三者交付(进入开发)前必须通过本规范自查。评审范围以**本期版本范围**为准。

## 设计要点

每个页面/功能在设计阶段必须明确:

- **范围边界**:本期做什么、**不做什么**(明确划清,避免开发自由发挥)。
- **事实边界**:外部样本只用于改进结构与表达;项目功能、字段、状态、公式、数值、权限和接口必须有项目内依据,无依据则标待决。
- **全状态覆盖**:每个页面定义 默认 / 空态 / 加载中 / 错误态 / 极端值(超长文本、超大列表、0/负数、最大值)。
- **流程闭环**:状态流转条件完善,无逻辑跳跃;非法流转有拦截。
- **多语言就绪**:所有文案走 i18n,预留长文案空间(ms-MY 通常更长),无硬编码。
- **设计系统一致**:色彩/字体/间距/组件遵循[设计系统](/overview/design/)。
- **全端响应式**:Web、H5、App 每页都定义 Desktop / Pad / Phone 的布局与操作契约；三类尺寸均可完成核心流程，禁止整页横向失控、重叠、裁切和关键操作不可达。
- **术语一致**:同一概念跨端(SYS/OPS/MCH/POS/KDS/H5)与跨语言术语统一。
- **无模糊表达**:不出现「应该 / 一般 / 尽量 / 可能」等模糊措辞,需求必须可判定。
- **时区选择器**:含时区字段的表单必须使用「带建议值必选 + 检测提示」模式;禁止「跟随系统」选项。

## 设计评审自查清单

PRD / 原型 / UI 每个功能点逐项回答;标注「无」也是有效答案,但不可留空。

| 维度 | 检查标准 |
|------|---------|
| 事实来源 | 每项功能、字段、状态、公式、数值、权限和接口均有项目内依据;外部样本未被当作需求来源 |
| 本期范围 | 明确本期实现内容 |
| 不做范围 | 明确本期**不做**的内容,划清边界 |
| 灰度策略 | 无 / 具体灰度规则 |
| 流程闭环 | 状态流转条件完善,无逻辑跳跃 |
| 异常覆盖 | 空态、极端值、错误提示语完整 |
| 操作记录 | 操作是否需要记录、可溯源 |
| 删除保留 | 删除数据是否保留(逻辑删 / 物理删) |
| 权限规则 | 数据隔离性等清晰完整(端/角色/租户/门店) |
| 计算逻辑 | 是否精确(金额、税 SST/GST、库存扣减、折扣) |
| 模式差异 | 列表 / 新增 / 编辑 / 查看或本页实际模式的入口、操作、可编辑范围和限制是否明确 |
| 字段联动 | 字段来源、默认/回填、必填、可编辑条件、约束、联动与清空规则是否完整 |
| 状态操作 | 各状态下操作的可见/可用条件、确认输入、副作用、失败反馈与可逆性是否明确 |
| 校验规则 | 文本长度 / 类型限制 / 特殊字符 / 正则 / 数值上下限 是否明确 |
| 数据模型 | 表结构完整(字段 / 类型 / 必填 / 默认 / 取值约束);无源模型标「源未定义,待补」不编造 |
| 时间审计 | 每个 `xx_at` 在同一模型内有 `xx_by BIGINT NOT NULL DEFAULT 0`;`0=system`;字段表与 DDL 一致 |
| 索引设计 | 高频查询 / 外键 / 唯一键 覆盖;条件唯一索引注明各数据库方言差异 |
| SQL 示例 | 每张表给出建表 + 索引 DDL,由字段/约束表逐字派生,不新增未声明字段 |
| 文案完整 | 多语言翻译齐全(zh-CN / en-US / ms-MY);预留 ms-MY 长文案空间;无源翻译标「待补」 |
| 配置来源 | 硬编码 / 开发配置 / 运维配置 / 用户配置;是否常变;是否多语言;是否枚举 |
| 状态覆盖 | 是否存在未定义或不明确状态;默认状态是否明确 |
| 影响核心流程 | 否 / 影响范围 |
| 影响历史数据 | 否 / 影响范围 + 数据库变更说明(up / down) |
| 是否依赖三方 | 否 / 依赖范围 |
| 版本兼容 | 无影响 / 兼容升级 / 强制升级 |
| 逻辑冲突 | 无 / 与已有功能的冲突点说明 |
| 可测试性 | 能写出完整测试用例 |
| 验收追踪 | 关键规则能追溯到测试用例和对应 Figma 屏/状态;暂缺设计稿时明确标记,不冒充已覆盖 |
| 响应式交付 | 每页有 Desktop / Pad / Phone 三类布局矩阵、Figma Screen/variant 与截图；核心信息/操作不因缩窄丢失 |
| 模糊描述 | 无「应该 / 一般 / 尽量」等模糊表达 |

**评审结论**:任一维度留空 → 退回补充;「计算逻辑 / 校验规则 / 状态覆盖 / 权限规则」有歧义 → 澄清后再开发;「影响历史数据」为是但无数据库变更说明 → 阻断;「可测试性」为否 → 需求未达可开发标准。

### 全端响应式交付契约

| 设备形态 | 验收区间 | 布局要求 | 操作要求 |
|---------|---------|---------|---------|
| Desktop | ≥1200px | 可使用常驻侧栏、多列、数据表格；内容宽度有上限，大屏不无限拉伸 | 键盘、鼠标、触控均可达，Focus 可见 |
| Pad | 768–1199px | 侧栏可折叠/抽屉，工具条允许换行，表单按内容改 1–2 列 | 触控目标 ≥44×44，横竖屏切换后状态不丢 |
| Phone | 320–767px | 单列优先；导航抽屉；复杂表格卡片化或在具名容器内滚动 | 核心操作不隐藏，底部操作与弹层避开安全区和虚拟键盘 |

- 页面不得把**整页横向滚动**作为响应式方案；确需横向信息密度的表格/图表只允许在自身容器内滚动，并保留关键列/标题与可发现的滚动反馈。
- 文本必须换行、截断或动态约束，不能遮挡相邻内容；系统字体放大后仍无重叠、裁切和按钮文字溢出。
- 每页 PRD 必填 `设备形态 -> 布局重排 -> 导航/操作 -> 数据呈现 -> 滚动 -> 安全区/键盘` 矩阵；高保真设计至少含三类代表尺寸，测试逐类截图并走通核心流程。

## PRD 写作规则(三读者)

> PRD 同时服务三个读者:**人**(评审业务正确性)、**AI**(生成生产代码)、**测试**(生成测试用例)。

### 1. 可判定性

- 每条需求可判真伪:禁止「应该 / 一般 / 尽量 / 可能 / 等 / 约 / 合理」。
- 枚举一律**闭集**(列全所有取值);默认值显式声明。
- 数值给完整边界:min / max / 步长 / 单位 / 精度 / 舍入规则。
- 时间声明判定基准(服务端 UTC 判定 / 客户端时区展示)与边界含否(如「≤ 2h(含)」)。

### 2. ID 可追溯体系(贯穿 PRD ↔ 原型 ↔ 任务 ↔ 用例 ↔ 代码)

| ID | 含义 | 定义处 | 被引用处 |
|----|------|--------|---------|
| `P{n}` | 页面 | 分端 · 页面清单 | 原型文件、用例 |
| `G{n}` / `C{n}` | 全局 / 局部组件 | 分端 · 组件清单 | 原型线框 `[C{n}]` 标注 |
| `A{n}` | 接口 / 实时通道 / 任务 | 分端 · 接口详述 | 组件数据来源、用例 |
| `R{n}` | 业务规则 | 总览 · 业务规则 | 各端页面、状态机、用例 |
| `SM-{对象}` | 状态机 | 总览 · 状态定义 | 业务流程、接口错误码、用例 |

同一规则只在定义处写一次,其余位置**只引用 ID 不复述**。**引用 ID 时必须带简短标签,全文零裸编号**,形如 `R19(POS开台代点)`、`A3(提交订单)`、`P2(订单工作台)`;标签用定义处的规范短名(≤8 字),全仓一致。**数字枚举状态一律配语义名**,如 `status=20(已下单锁定)`、`code 403(无权限)`。

### 3. 规则用表格,不用散文

- **模式 / 能力** → 表格:模式或场景 / 入口与角色 / 可见操作 / 可编辑范围 / 提交结果 / 限制。
- **字段契约** → 表格:字段 / 组件或类型 / 来源 / 默认或回填 / 必填 / 可编辑条件 / 约束与格式 / 联动与清空。校验提示另列 key,不把多条规则塞进一段话。
- **时间审计** → 每个 `xx_at` 同模型声明 `xx_by BIGINT NOT NULL DEFAULT 0`;用户动作写雪花用户 ID,系统动作写 0,事件未发生只看 `xx_at IS NULL`;运行 `node scripts/check-audit-actor-pairs.mjs` 验证。
- **状态操作** → 表格:当前状态 / 可见操作 / 可用条件 / 确认或必填输入 / 目标状态与副作用 / 不可用反馈 / 可逆性。
- **计算逻辑** → 表格:计算 ID / 输出 / 公式与变量 / 触发时机 / 输入与中间精度 / 输出与舍入 / 数字示例;至少 1 组示例,有边界时再给 1 组边界值,并声明守恒关系或不变量。
- **状态机** → 流转表(当前态 + 触发 + 条件 → 目标态 + 副作用);**未列出的流转一律非法**并声明拦截行为。
- **接口** → 契约表(方法 / 路径 / 鉴权 / 幂等 / 入参 / 出参 / 错误码)。

### 4. 行为三段式

每个用户操作写满三段:**触发**(谁在什么前置下做什么)→ **结果**(数据变化 + 用户反馈,确定性)→ **异常**(每个失败分支:错误码 → 提示 key → 用户去向)。只写 Happy Path 视为未完成。

### 5. 测试可推导性(PRD 合格的标尺)

- 校验规则表 → 等价类 / 边界值用例;状态机流转表 → 合法流转 + 非法拦截用例;操作清单异常列 → 错误推测用例;验收标准量化 → 性能断言。
- **反向检验**:任取一条规则,问「能否不加追问写出用例」——不能则该条没写清。

### 6. 人审友好

- 总览在前讲业务(目标 / 范围 / 术语 / 流程),精确表格下沉到分端。
- 流程与状态机配 mermaid 图:**人看图、AI 读表**,两者并存且必须一致。
- 每页配 ASCII 线框对照。

### 7. 参考资料隔离

- 其他产品的 PRD、截图和说明只用于学习章节组织、表格维度、状态表达、计算举例和评审留痕。
- 参考资料中的业务名词、角色、字段、枚举、公式、数值、权限、接口与页面不得直接进入本项目。
- 改写前先列“吸收的方法 / 明确不带入的业务内容”;改写后抽查每条新增事实能否指向本项目 PRD、Figma 或实现。找不到依据的内容进入待决问题,不补写成确定需求。

## PRD 文档结构

**多端版本拆分为「总览 + 分端」多文件**(`prd.md` + `prd-{端}.md`)。模板见 [PRD 模板](/overview/rules/prd-template/),新写 / 重构一律从模板起步。

### 总览文档 `prd.md`

1. 更新记录 2. 问题陈述与目标(可量化成功标准) 3. 范围边界 4. 术语表 5. 角色与权限 6. 数据模型 7. 状态定义(`SM-{对象}`) 8. 业务流程(仅跨端联动) 9. 业务规则(`R{n}` 单一来源) 10. 数据与影响面 11. 依赖与兼容 / 灰度 / 逻辑冲突 12. 验收标准(量化) 13. 分端文档索引 14. 版本级设计自查清单 15. 待决问题(Open Questions)。

### 分端文档 `prd-{端}.md`

1. 端目标 / 范围 2. 端内业务流程 3. 页面清单(站点地图) 4. 页面详述(逐页 · 组件级) 5. 后端 / 接口 / 实时通道详述 6. 异常与空态汇总 7. 验收 / 分端自查清单。

**去重铁律**:`prd.md` 只放**跨端共享**内容;`prd-{端}.md` 放**该端全部细节**。同一内容只允许一个定义处,另一处引用。

## 原型制作约定

### 格式与定位

- 原型统一为 **ASCII 线框(纯文本中低保真)**:用字符画出页面布局、区块划分、组件位置与层级;**结构、组件、文案、状态为真**,视觉(配色 / 字体 / 精细间距)刻意不做。
- 原型是**结构 / 布局 / 交互契约**,面向三个读者:人(读布局)、PRD(并排对照)、AI(据此生成高保真页面与代码)。
- **产出链**:PRD(结构 / 组件 / 数据 / 规则)+ ASCII 线框(布局)→ **高保真设计稿**(视觉);生产代码以 **PRD + 接口规约 + 高保真设计稿** 为输入,在目标技术栈重写。
- ASCII 是**唯一低保真原型真源**;高保真设计稿是其**下游派生产物**,不反向充当结构契约(线框 / PRD 变更后重新生成)。

### 文件组织

- **按版本存放**:`vX.Y/prototype/{端}/{页面}.txt`,或直接内联进 PRD 页面详述的「线框」块;路径一律 ASCII(customer / mch / pos / kds / sys / ops / www / num),禁止中文。
- **每屏一块**,与 PRD 页面 `P{n}` 一一对应。
- 纯文本、零构建、**零依赖**(断网、纯 Markdown 即可读)。

### 画法与标注(机器可解析)

- 用 box-drawing 字符(`┌─┐│└┘├┤`)或朴素 `+--|` 画框;层级用缩进 / 嵌套框表达。
- **组件标 ID**:框内 / 框旁标 `[C1 菜品卡片]`、`[G1 顶部信息条]`,与 PRD 组件清单一致。
- **文案标 i18n**:关键文案后注 `«key»`,与 `i18n.csv` 对应。
- **状态标注**:同屏多态分别画,或框内注 `{state: empty/loading/error}`;文案取最长语言(ms-MY)验证是否溢出。

示例(一屏线框):

```text
┌─ [G1 顶部信息条]  门店名 · 桌号 «mch.header.table» ────────┐
│                                                          │
│  [C1 菜品卡片]           [C1 菜品卡片]                     │
│  ┌────────────┐         ┌────────────┐                   │
│  │ 图  名称    │         │ 图  名称    │   {state: default}│
│  │    RM 12.00 │         │    RM 8.00  │                   │
│  └────────────┘         └────────────┘                   │
│                                                          │
│  [C5 购物车条]  合计 RM 20.00        「去结算」«...checkout»│
└──────────────────────────────────────────────────────────┘
```

### 生成高保真设计稿

- 输入 = PRD 页面详述(组件清单 / 数据来源 / 操作)+ 该屏 ASCII 线框(布局)。
- 输出 = 高保真设计稿,套用[设计系统](/overview/design/)的令牌与组件。
- 高保真设计稿是**视觉交付物**,不回写为原型契约。

:::note
视觉部分联动[设计系统](/overview/design/),可测试性联动[测试规约](/overview/rules/test/)。
:::
