## 业务流程图

绘制规范:

- 每条流程必须有明确的**起点与终点**,不留悬空分支。
- 关键节点标注**触发条件**与**操作角色 / 端**。
- 覆盖主流程(Happy Path)+ **异常分支**(失败、超时、取消、回滚)。
- 跨端流程标注各端职责与交接点(如 顾客端 → 收银端 → 厨房端)。

## 数据流转图 / 状态机

绘制规范:

- **状态枚举完整**:列出全部状态,无未定义或含义不明的状态。
- **默认状态明确**:标明初始状态与终止状态。
- **流转条件显式**:每条状态流转标注触发条件,无逻辑跳跃。
- **非法流转拦截**:未声明的流转视为非法,必须被拦截。
- **幂等与并发**:标注重复触发、并发操作下的状态处理。
- **跨端一致**:同一业务实体在多端的状态最终一致(联动[架构原则](/Volumes/Macintosh/Projects/aspeed/7link-mall/7link-mall-doc/src/content/docs/overview/rules/arch.md)闭环原则)。

### 状态机文档要素

| 要素 | 说明 |
|------|------|
| 状态列表 | 全部状态及含义 |
| 初始 / 终止状态 | 进入与结束节点 |
| 流转表 | 当前状态 + 触发条件 → 目标状态 |
| 异常处理 | 失败 / 超时 / 取消 对应的状态归属 |
| 操作记录 | 关键流转是否需留痕可溯源 |


> 人看图、AI 读表——mermaid 图与流转表并存且必须一致。
