这是一份**平台/语言无关的规范**。它规定后台增删改查(CRUD)统一收敛为一个**声明式资源描述符(Resource Descriptor)**:每个业务资源只声明**一份描述符**,列表、表单、详情、克隆、导入导出、删除确认由通用引擎从中**派生**。任意技术栈都可实现同一份描述符概念——描述的是**契约与行为**,不绑定任何语言或框架。

> 核心主张:**后续所有管理页面都声明一份资源描述符即可;描述符能力不足时,再逐层下钻补充**。见文末[逐层补充方法论](#逐层补充方法论)。

本文示例用 **YAML** 书写描述符(纯声明式数据,任意语言可承载)。

## 角色与数据流

```
声明层    资源描述符 (Resource Descriptor)           ← 业务只写这一份
          ├─ 列表壳  绑定 → 表格引擎 (AutoTable)
          └─ 表单壳  绑定 → 表单引擎 (AutoForm)   mode = 新增|编辑|详情|克隆
─────────────────────────────────────────────────────────────
派生层    表格引擎 → 列渲染 + 标准操作(编辑/克隆/删除)+ 行点击(详情)
          表单引擎 → 取详情 / 提交新增 / 提交编辑 / 入站映射 / 出站映射
─────────────────────────────────────────────────────────────
渲染层    列渲染器(text/image/icon/…)   字段渲染器(text/select/image/关联/自定义…)
─────────────────────────────────────────────────────────────
基础层    表格 / 徽章 / …                输入框 / 下拉 / 开关 / 按钮 / …
```

规范要点:**资源描述符是唯一真源**,其余全由其纯推导。特例通过描述符内的可选钩子(入站/出站映射、额外操作、条件显隐、自定义字段)挂入,**不得**改动通用引擎。

## 资源描述符契约

一份描述符同时刻画表单、表格、接口与行为。字段语义如下(类型以行为描述,非某语言类型):

| 分组 | 键 | 语义 |
|---|---|---|
| **路由/接口** | `basePath` | 前端导航基址(如 `/mch/stores`) |
| | `apiPath` | 接口基址,缺省同 `basePath` |
| | `createApiPath` | 仅「新增」走独立端点时覆盖 |
| | `import` | 导入任务:`{ path, mediaTypes, templatePath? }`;`path` 必须为 `/api/v1/{resources}/imports`,声明了才出「导入 ▾」 |
| | `export` | 导出任务:`{ path, mediaTypes }`;`path` 必须为 `/api/v1/{resources}/exports`,声明了才出「导出 ▾」(选类型导当前筛选结果) |
| | `idKey` | 行主键,默认 `id` |
| **表单** | `form` | **字段描述符集合**(见[表单规范](#表单规范-autoform)) |
| | `inbound` | 入站映射:服务端记录 → 表单值(拆多语言、解析结构) |
| | `outbound` | 出站映射:表单值 → 服务端记录(拼多语言、缩放价格) |
| | `editable` | 为否时表单无提交(只读资源) |
| **表格** | `columns` | 列描述符集合 |
| | `filters` | 筛选工具条字段 |
| | `order` | 默认排序(如 `created_at: DESC`) |
| | `filterMode` | 过滤方言:`simple`(默认)/ `advanced`(解锁 OR/IN/BETWEEN/分组) |
| | `staticFilter` | 每次请求恒定注入的过滤(如 `source: local`) |
| | `sticky` | 四向吸附:表头 / 表尾分页 / 左冻结列(`pin:left`)/ 右操作列(`pin:right`);表格填满剩余空间,仅 items 区滚动 |
| | `refresh` | 定时刷新:`{ intervals:[off,3s,5s,10s,15s,30s,1m,5m,10m,15m,30m], default: off }`;按钮点击=手动刷新、下三角=选间隔 |
| | `extraActions` | 插在「删除」前的额外行操作 |
| | `deleteConfirm` | 自定义删除确认文案(按业务措辞) |
| **能力开关** | `features` | `add/edit/copy/detail/delete/export` 逐项关闭(默认全开) |

## 表单规范(AutoForm)

`form` 是**字段名 → 字段描述符**的有序映射。键名 `--- xxx` 且 `type: title` 表示分节标题。

### 布局与垂直节奏

- 当前可见字段为`1–6`项时，使用 500px 单列并在表单内容区水平居中。
- 当前可见字段为`7+`项时，恢复动态响应式栅格；半宽字段按两列排列，长字段继续独占整行。
- Section Title 始终填满 AutoForm 内容容器宽度，不随 500px 字段列收窄。
- Section Title 到首字段为 16px，同列字段块之间为 16px，Label 到控件为 6px。
- Input/NumberInput 等输入型字段可保持标准字段高度；Radio/Switch/Checkbox 等短控件的字段外框必须 Hug 真实内容，不得用固定高度制造隐形空白。
- 正式业务 Screen 必须引用 `03 Molecules` 的 AutoForm 组件实例，不得在 Screen 内重复内联组合标题与字段栅格。当前紧凑业务表单统一收口于 [Molecule / AutoForm Compact Forms](https://www.figma.com/design/HPojH5xVmyhO4KJeE3XFTH/7link-mall-web-ALL?node-id=3903-15790)。

### 底部操作栏

AutoForm 所在的 CrudFormPage/配置页统一复用 Sticky Action Bar。按钮组在内容区水平居中，间距 8px；1 个可见按钮最小宽 240px，2 个时每个最小宽 180px，3 个时每个最小宽 120px。标准编辑表单使用`[取消][保存/提交]`。

### 字段类型(与渲染无关的语义枚举)

```
基础   text textarea number password email code
选择   select multi-select checkbox checkbox-group switch radio bool-select
日期   date dateRange datetime datetimeRange time timeRange
富媒体 price rich-text code-editor image media location
关联   remote-select remote-multi-select relation-list
结构   tabs title custom
```

> `remote-*` 关联字段以 `url` 拉取候选、`labelKey/valueKey` 指定显示/取值键——**任意语言实现只需能发起该请求并渲染选项**。`custom` 是逃生舱:挂平台特有渲染件。

### 字段描述符属性

| 属性 | 语义 |
|---|---|
| `label` | 字段标签(可为动态,依当前值取) |
| `type` | 上表之一 |
| `value` | 默认值 |
| `required` | 必填(可为条件:依其他字段) |
| `show` | 条件显隐谓词;为假则该字段(及所属分节标题)隐藏 |
| `disabled` | 条件禁用 |
| `copy` | 为否时**克隆模式重置为默认**(编号/SKU 不该被克隆) |
| `col` | 两列栅格跨度:`1` 半宽 / `2` 全宽(默认) |
| `config` | 渲染配置:选项 / 占位 / 行高 / 上下限 / 关联 url·键 / 校验规则 / 最大文件数… |

### 四业务模式(FormMode)

**同一份 `form` 覆盖四模式,禁止各维护一套**:

| 模式 | 行为 |
|---|---|
| `新增 add` | 空表单,全部可编辑 |
| `编辑 edit` | 预填当前记录,可编辑 |
| `详情 detail` | 预填 + **强制只读**(字段渲染为只读块) |
| `克隆 copy` | 预填被克隆对象,但 `copy:false` 字段重置为默认,可编辑 |

> 规范:**详情 = 编辑的只读态,克隆 = 新增的预填态**——三者共用同一 `form`。

### 入站 / 出站映射

服务端数据模型与表单字段常不 1:1(多语言、结构化 JSON、字段别名、金额单位)。规范要求把差异**收拢到两个纯映射**,而非污染字段声明:

- **入站(inbound)**:服务端记录 → 表单值。容错服务端字段别名。
- **出站(outbound)**:表单值 → 服务端记录。

## 表格规范(AutoTable)

**列描述符**:`field` / `name` / `type`(text·image·icon·qrcode·area)/ `sortable` / `width` / `format(值,行)`(枚举 → 文案)/ `color` / `onclick` / `pin`(`left`·`right` 冻结列)。引擎在业务列前自动装配 48px 的本页本地序号 `#`(从 1 递增、`pin:left`、不是业务 ID),所有 AutoTable 不得省略。实体列表末尾自动装配 120px 的`操作`列(`pin:right`);只读实体也至少逐行提供`查看详情`,只有 PRD 明确无详情页并写明替代信息承载方式时才可省略。操作集合必须继续按资源归属、角色权限与行状态展开;多于一项时改用 24px IconButton + 4px gap 的紧凑组,每项有 tooltip/aria-label。危险操作保留语义但不抢占默认视觉权重:行内删除默认中性 ghost,hover/focus 与确认阶段再切 destructive 红色。

### 统一工具条(所有列表同一套,只有筛选条件随业务变)

列表页顶部是一条**固定装配**的工具条,组件与行为全端一致——业务只改 `filters` 的字段,**按钮组与查询/重置永远配套,不逐页自定义**。

> **全部标配、默认全开**:下列按钮都是每个列表的默认能力,**特定业务才用 `features` 显式关掉某项**——例如订单不允许后台手动创建,置 `features.add: false`,「＋ 新增」即消失,其余照常。

- **主操作区(右上)**——按 `features` 与端点声明出现:
  - **[＋ 新增]**:`features.add` 开启时,列表上方出此按钮,开 AutoForm 新增态。
  - **动态列 ▾**:依 `columns` 生成,勾选显示 / 隐藏 / 排序列,选择**按账号 × 资源持久化**。
  - **导入 ▾**:`import` 声明才出;点击打开 [ImportDialog](molecules.md#导入弹窗-importdialog),由资源描述符覆盖标题、标准媒体类型、大小/数量/最大行数限制和可选 `templatePath`;选择文件不上传,点击 Import 后创建任务并轮询成员 `Location`;全部成功倒计时关闭,部分失败从任务 `/error-report` 获取报告。
  - **导出 ▾**:`export` 声明才出;下拉按 `mediaTypes` 选择输出类型,以 `POST` 创建任务并轮询成员 `Location`,完成后从 `/content` 下载**当前筛选结果**。
  - **刷新 ▾**:**点按钮 = 立即手动刷新**;**点右侧下三角 = 选定时**——`关闭 / 3s / 5s / 10s / 15s / 30s / 1m / 5m / 10m / 15m / 30m`,选中即起定时、再选「关闭」停。默认关闭。
- **筛选条(其下)**:`filters` 逐字段渲染(关键词 / 下拉 / 日期…)+ 固定 **[查询] [重置]**。每项含 `field` / `type`(string·number·date·select·boolean)/ `conditions`(`like`·`eq`…)/ `options`。**只有筛选条件随业务不同**,组件与查询/重置恒定。

### 尺寸与吸附(所有列表统一)

- 表格**填满内容区剩余空间**(占满宽高),不由行数撑高、不留空档。
- **四向吸附 `sticky`**:表头 / 表尾(分页)/ 左冻结列(`pin:left`)/ 右操作列(`pin:right`)固定不动,**仅 items 区自身左右 + 上下滚动**。
- Header 与所有 Body Row 必须使用同一列宽数组:`#` 固定 48px,实体操作列固定 120px,中间数据列按基准宽度 + grow 平摊剩余空间。最终数组还必须形成稳定视觉节奏:主名称/描述列允许更宽,来源/状态/调整等同类短字段优先等宽,不得只满足总宽而出现无语义的细碎宽差;每个可见 Row 的列 x/width/align 都与 Header 一致。左 `#` 冻结边缘显示描边与向右阴影,右操作列左缘显示描边与向左阴影,items 区显示与 overflow 方向一致的滚动条。
- MCH Outlet 正式业务集:`AutoTable / Outlet Items` `3870:34185` 与 `AutoTable / Outlet Categories` `3870:34482`,统一暴露 `View=actual|hq|custom|local`;商品列宽为 `[48,80,280,156,156,156,156,120]`,分类列宽为 `[48,336,216,216,216,120]`。

### 行为

- **标准行操作流水线**(引擎自动装配,顺序固定):**编辑 · 克隆 · [extraActions] · 删除**。删除 = 弹 `deleteConfirm` 文案 → 确认 → 调用删除端点 → 刷新。
- **权限动作矩阵**:只读继承行至少`查看`;自有且可维护的行在查看之外装配资源声明允许的动作。本店独有商品与本店独有分类均=`查看/编辑/克隆/删除`;无权限动作隐藏,临时不可用动作 disabled 并给出原因,不得把有维护权限的行降级成只有查看。
- **三态**:`{empty}` 缺省提示 · `{loading}` 骨架行 · `{error}` 重试——由引擎统一渲染,不逐页处理。

## 逐层补充方法论

当声明式配置不够用(如结构化的规格/加料/套餐编辑),**不要绕开描述符另起炉灶**,而是用 `type: custom` 挂专用编辑件,或用 `rich-text` 等高级类型。商品进阶资源即如此:规格/加料/套餐/多语言富文本/字段策略全走 `custom`,仍是同一份描述符。

**下钻优先级阶梯**——停在第一个够用的层级:

1. **配置搞定?** 换 `type` / 加 `show` / 校验 / `format` / 入站·出站映射——**不写组件**。
2. **单资源特例?** `type: custom` 挂一个渲染件,只在该资源描述符里(如时区字段、规格编辑器)。
3. **多资源复用?** 才升格为正式字段类型(进字段渲染注册表)或补分子/原子,**回流到组件库/规范**。

> 铁律:**先声明描述符,不够再逐层补,永远从最省的一层开始**。禁止绕过封装手搓页面——那会让四模式一致性、吸附、导入导出、多语言退化为各页各端自维护,规范随之瓦解。

## 跨端/跨语言落地

同一份资源描述符概念应能在各端复用;差异仅在**渲染层绑定**,声明层与行为契约不变:

| 端 | 声明层 | 渲染绑定 |
|---|---|---|
| Web 后台(MCH/SYS/OPS) | 资源描述符 | 后台 Web 参考实现 |
| POS / KDS(平板) | 同一描述符概念 | 平板端控件 |
| 其他技术栈 | 同一描述符概念 | 各自基础控件 |

平台**只需实现**:字段类型枚举 → 控件的渲染注册、四模式行为、入站/出站映射钩子、标准操作流水线、吸附与过滤方言。满足这些即合规,内部用何语言/框架不限。
